# dx03v2 API

Message-board API reference: endpoints, errors, configuration and curl examples. The behavior
described here is covered by `api/test` and `e2e/smoke.mjs`. This is the same API as `dx01v2` and
`dx02v2` (only names change; the parity routine is in `docs/MAINTENANCE.md`).

The examples use the Compose stack (`http://127.0.0.1:8080`, with the API behind nginx at `/api/`).
For `DELETE`, load the token from the `.env` generated by `scripts/dev-env.sh` without printing it:

```bash
BASE=http://127.0.0.1:8080
ADMIN_TOKEN="$(sed -n 's/^ADMIN_TOKEN=//p' .env)"
```

## Endpoints

| Method and path | Description | Responses |
|---|---|---|
| `GET /healthz` | Liveness, without dependencies | 200 `{"status":"ok"}` |
| `GET /readyz` | Readiness: `SELECT 1` within 1 s and process not shutting down | 200 `{"status":"ready"}`; 503 `{"status":"db_unavailable"}` or `{"status":"shutting_down"}` |
| `GET /api/info` | Build and runtime identity (never secrets or database contents) | 200 `{"name","version","commit","environment","uptimeSeconds"}` |
| `GET /api/messages?limit=N` | Messages from newest to oldest; integer `limit` from 1 to 100, default 20 | 200 `{"items":[{"id","author","text","createdAt"}]}`; 400 |
| `POST /api/messages` | Create a message; JSON body `{"author","text"}` | 201 with the message and `Location`; 400, 413, 415, 429 |
| `DELETE /api/messages/:id` | Delete a message; requires `Authorization: Bearer <ADMIN_TOKEN>` | 204; 400, 401, 404; 503 `admin_disabled` when `ADMIN_TOKEN` is not configured |
| `GET /api/stats` | Message count | 200 `{"messages":N}` |
| `GET /metrics` (port `METRICS_PORT`, 9464) | OpenMetrics metrics: Node.js defaults and `http_request_duration_seconds{method,route,status_code}`, with the request `trace_id` as an exemplar when tracing is enabled | 200; not exposed by the web server or Gateway |

`/healthz` and `/readyz` do not pass through nginx (nginx's `/healthz` belongs to the web server).
Kubernetes probes the API directly on the Pod; on Google Cloud, the Gateway load balancer uses
`/readyz` as the API health check (`api` HealthCheckPolicy, port 3000).

`POST` input rules:

- `author`: string, 1–40 characters after `trim`; `text`: 1–280 characters after `trim`.
- Control characters (C0, DEL, C1) and extra fields are rejected (`strictObject`).
- Text is stored as received, without HTML escaping; the page renders it as text.
- Per-client write limit (`req.ip`): `RATE_LIMIT_WRITE_PER_MINUTE` (default 10) per minute, counted
  before validation. Above the limit: 429 with `Retry-After`, `RateLimit-Policy` and `RateLimit`
  headers (IETF draft 8).

## Errors

Every error has the same format, without internal details:

```json
{"error":{"code":"validation_error","message":"author: must have 1 to 40 characters","requestId":"3f1c..."}}
```

| Status | `code` | When |
|---|---|---|
| 400 | `validation_error` | Invalid body, `limit` or `id` (summary of up to five zod failures) |
| 400 | `invalid_json` | Malformed JSON |
| 400 | `bad_request` | Body could not be read |
| 401 | `unauthorized` | Missing or incorrect admin token (with `WWW-Authenticate: Bearer`) |
| 404 | `not_found` | Unknown route or nonexistent message |
| 413 | `payload_too_large` | Body above 10 kb (nginx returns the same JSON above 64k) |
| 415 | `unsupported_media_type` | `Content-Type` other than `application/json`, or a non-UTF-8 charset |
| 429 | `rate_limited` | Write limit reached |
| 500 | `internal_error` | Unexpected failure (details go only to the log) |
| 503 | `db_unavailable` | Database unavailable |
| 503 | `admin_disabled` | `DELETE` without a configured `ADMIN_TOKEN` |
| 503 | `api_unavailable` | nginx response when the API does not respond (upstream 502/503/504) |

Every response includes `X-Request-Id`. The incoming value is reused only if it matches
`^[A-Za-z0-9-]{1,64}$`; otherwise the API generates a UUID. The same ID appears in every log line
for the request and in the `requestId` field of errors. Google Cloud's global external Application
Load Balancer documentation did not specify whether it forwards, replaces or appends
`X-Request-Id` (checked 2026-10-11). The smoke test with `SMOKE_EDGE=gke` therefore checks the
security property: a safe ID returns unchanged or as a UUID, an unsafe ID never returns, and two
requests never share an ID.

## Headers

- API: helmet with CSP `default-src 'none'; frame-ancestors 'none'`,
  `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, no `X-Powered-By`, no HSTS (the edge
  decides it), and no CORS.
- Web (nginx): CSP `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`,
  `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `Cross-Origin-Opener-Policy`,
  `Cross-Origin-Embedder-Policy: require-corp` and `Cross-Origin-Resource-Policy: same-origin` on
  every response, including assets and errors. HSTS is sent only when `X-Forwarded-Proto` is `https`.

## Configuration (environment variables)

| Variable | Default | Notes |
|---|---|---|
| `APP_ENV` | `local` | `local`, `ci`, `kind` or `lab` |
| `PORT` / `METRICS_PORT` | `3000` / `9464` | Must differ |
| `TRUST_PROXY_HOPS` | `0` | Number of proxies in front of the API: 1 in Compose and kind (nginx), 2 behind the Google Cloud Application Load Balancer (Google Front End + load balancer); never `true` |
| `LOG_LEVEL` | `info` | `fatal`, `error`, `warn`, `info`, `debug`, `trace`, `silent` |
| `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` | — | Required (`db-credentials` Secret) |
| `DB_PORT` | `5432` | |
| `DB_SSL_MODE` | `disable` | `disable`, `require` or `verify-full`; only `verify-full` with `APP_ENV=lab` |
| `DB_SSL_CA_FILE` | — | Required with `verify-full` (PEM; `/etc/cloudsql-ca/ca.pem` on Google Cloud) |
| `DB_POOL_MAX` | `10` | 1–100 |
| `RATE_LIMIT_WRITE_PER_MINUTE` | `10` | 1–10000 |
| `ADMIN_TOKEN` | — | Optional; at least 32 characters when set (`app-secrets` Secret) |
| `GIT_SHA` | `unknown` | Commit shown in `/api/info` (passed to images through a build argument) |
| `SHUTDOWN_TIMEOUT_MS` | `10000` | Graceful shutdown deadline before forced exit |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | — | Optional http(s) URL of an OTLP/HTTP receiver (the platform OpenTelemetry Collector). When set, the API exports request and query spans, continues incoming W3C `traceparent`, and writes `trace_id`/`span_id` to logs. When unset, nothing is exported |

Any invalid value stops the process at startup with a list of problems, without echoing values.

## Curl examples

```bash
curl -fsS "$BASE/api/info"
curl -fsS "$BASE/api/messages?limit=5"
curl -sS -X POST "$BASE/api/messages" -H 'Content-Type: application/json' \
  -d '{"author":"Ana","text":"Hello, <b>board</b>!"}'                     # 201, text stored as sent
curl -sS -X POST "$BASE/api/messages" -H 'Content-Type: application/json' \
  -d '{"author":"","text":"x"}'                                          # 400 validation_error
curl -sS -X POST "$BASE/api/messages" -H 'Content-Type: application/json' -d '{"author":'  # 400 invalid_json
curl -sS -o /dev/null -w '%{http_code}\n' -X DELETE "$BASE/api/messages/1"   # 401
curl -sS -o /dev/null -w '%{http_code}\n' -X DELETE "$BASE/api/messages/1" \
  -H "Authorization: Bearer $ADMIN_TOKEN"                                  # 204 (or 404 if absent)
curl -fsS "$BASE/api/stats"
curl -sSI "$BASE/api/info" -H 'X-Request-Id: my-test-123' | grep -i x-request-id
```

Rate limit with a forged `X-Forwarded-For` (the limit is unchanged because `req.ip` comes from the
trusted proxy):

```bash
for i in $(seq 1 12); do
  curl -s -o /dev/null -w '%{http_code} ' -X POST "$BASE/api/messages" \
    -H 'Content-Type: application/json' -H "X-Forwarded-For: 198.51.100.$i" -d '{"author":"","text":""}'
done; echo   # 400 ... 400 429 429
```

Metrics (inside the Compose network; the port is not published):

```bash
docker compose -p dx03v2-dev exec web wget -qO- http://api:9464/metrics | head
```
