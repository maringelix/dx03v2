# Contributing

Thanks for helping. This lab only claims what its harness proves, so every change goes through it.

Forking the lab to run it on your own machine and cloud account? Start with [FORK.md](FORK.md).

## Workflow

1. Open an issue for anything non-trivial (bugs: use the bug report form).
2. Branch from `main`; use [Conventional Commits](https://www.conventionalcommits.org/)
   (`feat:`, `fix:`, `docs:`, `chore:`, `ci:`, `refactor:`, `test:`).
3. `make tools` once, then `HARNESS_STRICT=1 make verify` before pushing; also `make build` and
   `make e2e` when you change images, manifests or the app. Windows/macOS: use the devcontainer.
4. Optional fast feedback: `pre-commit install` (hooks in `.pre-commit-config.yaml`).
5. Open a PR and complete the Definition of Done in the template. Merges are squash-only.

## Rules that matter most

- No secrets or real identifiers (project IDs and numbers, service account e-mails, workload
  identity providers, IPs, e-mails, hostnames) anywhere, including examples and test data. Use the
  placeholders of `AGENTS.md` (`tx03v2-lab-example`, `000000000000`, `you@example.com`). Local
  secrets come from `scripts/dev-env.sh`.
- Do not weaken checks, lower coverage thresholds or add scanner ignores without `statement` and
  `expired_at`.
- Explain any IAM, NetworkPolicy, RBAC, Gateway/HTTPRoute, load balancer range or CORS widening in
  the PR. Google Cloud access is Workload Identity Federation only (no service account keys).
- Contract changes (`docs/CONTRACT.md`) need a coordinated PR in `tx03v2` and a version bump.
- The app (`api/`, `web/`, `e2e/`) is the same as in `dx01v2` and `dx02v2`: port app changes to the
  other app repositories (docs/MAINTENANCE.md, parity routine).
- Pin new dependencies (exact npm versions and the lockfile), actions (full commit SHA +
  `# vX.Y.Z`), images (digest) and tools (version + SHA256). `deploy/k8s/schemas` is generated by
  `scripts/update-crd-schemas.sh`; never edit it by hand.
- UI: no inline styles or scripts (the CSP forbids them); render user text as text.
- All public documentation, UI text, examples, comments and contributor guidance use English.
  Keep one README and link the [family getting started guide](https://github.com/maringelix/tx00v2/blob/main/docs/GETTING_STARTED.md).

## Cloud runs

You never need a Google Cloud project to contribute. If you deploy the app in your own project, read
the cost section of the README first, follow `docs/RUNBOOK.md` and share the result with the
**Cloud run report** issue form.

The full rule list is in [docs/GUARDRAILS.md](docs/GUARDRAILS.md); agents and humans also follow
[AGENTS.md](AGENTS.md).
